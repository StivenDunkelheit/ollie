# Сценарий Make: генерация урока

Готовый файл для импорта: **[ollie-generation.blueprint.json](ollie-generation.blueprint.json)**

Он собирается командой `npm run make:blueprint` и руками не правится — генератор
экранирует все строки сам и проверяет результат. Ниже описано, что внутри и
почему сделано именно так.

```
Webhook → Response 200 → 1. Аналіз → 2. План → 3. Побудова → Callback в Ollie
```

Три вызова Claude Haiku 4.5, каждый решает одну задачу. Разбивка не прихоть:
Haiku дешёвая, но на одном запросе, где надо разом оценить сорок задач, отобрать
десять, выстроить по сложности и заполнить большую схему, — она сбоит. По шагам
справляется. И когда урок выйдет плохим, видно, какой именно шаг ошибся.

## Импорт

1. Make → **Create a new scenario** → меню «…» справа сверху → **Import Blueprint**.
2. В трёх модулях с обращением к Anthropic заменить `ВСТАВТЕ_СВІЙ_ANTHROPIC_API_KEY`
   на свой ключ из [platform.claude.com](https://platform.claude.com).
3. Убедиться, что модуль вебхука подхватил ваш `My OLLIO DATA`. Если нет —
   выбрать его в списке.
4. Добавить error handler (см. ниже) — вручную, blueprint его не переносит.
5. Включить сценарий.

Чтобы Make узнал структуру входящих данных, при выключенном сценарии нажмите
на вебхуке **Redetermine data structure** и отправьте образец:

```bash
curl -X POST http://localhost:3000/api/dev/generation-sample
```

## Модули

| # | Модуль | Что делает |
|---|---|---|
| 2 | Custom webhook | Принимает задание от Ollie |
| 3 | Webhook response | Сразу отвечает `200 {"accepted":true}` |
| 4 | HTTP → Anthropic | Аналіз задач |
| 5 | HTTP → Anthropic | План уроку |
| 6 | HTTP → Anthropic | Побудова уроку за схемою |
| 7 | HTTP → Ollie | Віддає готовий урок на callback |

**Webhook response обязателен и стоит вторым.** Без него Make держит соединение
до конца сценария, а приложение ждёт ответа 30 секунд и пометит урок
неудавшимся, хотя генерация идёт.

Вызовы идут по HTTP, а не через приложение Anthropic в Make: нужен точный
контроль над телом запроса, в частности `output_config.format` для третьего
шага — схема подставляется как `{{2.output_schema}}` прямо из вебхука.

## Что решает какой шаг

**1. Аналіз** разбирает каждую задачу: сложность 1–5, навык, дубликат ли,
учебная ценность, ответ если он есть в тексте. Ничего не отбирает.

**2. План** принимает все решения: что взять, в каком порядке, каким
интерактивом подать, где награда и Boss Battle. Правила подставляются из
вебхука, поэтому меняются в коде приложения без правок сценария. В конце
промпта модель обязана себя проверить: не падает ли сложность, сложнее ли
последнее задание первого, не стоят ли два одинаковых интерактива подряд.

**3. Побудова** решений не принимает — разворачивает готовый план в схему.
Поэтому почти не ошибается.

## Два неочевидных решения

### Промежуточный формат — без кавычек и переносов строк

Первые два шага отвечают не JSON, а строкой вида:

```
n=1 | text=Обчисліть 3/4 + 1/4 | difficulty=1 | skill=додавання дробів | duplicate_of=- | value=high | answer=1 ;; n=2 | …
```

Причина техническая. Ответ шага подставляется в тело следующего запроса внутрь
JSON-строки, а Make подставляемые значения **не экранирует**. Кавычка или
перенос строки в ответе разорвут тело запроса. Обходят это выражениями
`replace()`, но проверить их работу без запуска нельзя, и ошибка вылезет не при
импорте, а на первом же уроке.

Формат без кавычек убирает проблему целиком: экранировать нечего. Для
промежуточных данных читаемость роли не играет — их видит только следующая
модель.

Третий шаг возвращает нормальный JSON: он подставляется в callback на месте
значения (`"lesson": {{6.…}}`), а не внутрь строки, — там экранирование не нужно.

### Входные данные приходят уже экранированными

Текст задач содержит переносы строк, правила — тоже. Приложение отдаёт их
дважды: как есть (`input.source_text`, `rules.*`) и подготовленными к вставке
в JSON-строку (`escaped.source_text`, `escaped.rules.*`). Сценарий использует
вторые.

Генератор проверяет это автоматически: разбирает тело каждого запроса,
находит подстановки внутри строковых литералов и падает, если встретил
неэкранированную. Проверка работающая — при попытке подставить сырой
`input.source_text` сборка останавливается с ошибкой.

## Error handler

Blueprint его не переносит, добавьте вручную: правой кнопкой по модулю 6 →
**Add error handler** → **Resume** → внутри HTTP-модуль на `{{2.callback.url}}`:

```
{
  "lesson_id": "{{2.lesson_id}}",
  "token": "{{2.callback.token}}",
  "status": "failed",
  "error": "Помилка генерації"
}
```

Без него сорвавшаяся генерация оставит урок в состоянии «генерується» навсегда,
и преподаватель будет смотреть на крутящийся индикатор.

## Что делает приложение с результатом

Урок принимается, только если проходит проверки:

| Проверка | Что отклоняется |
|---|---|
| Схема | лишние или отсутствующие поля, неверные типы |
| Ссылки | `correct_id` не из `options`, пропуск без записи в `blanks`, `hp` ≠ числу раундов |
| Кривая сложности | задание легче предыдущего |
| Рост сложности | последнее задание не сложнее первого |

При отказе приходит `422` со списком причин в поле `issues` — он виден в истории
выполнения Make. Промпт правится по конкретным претензиям, а не наугад.

## Стоимость

Haiku 4.5 — $1 за миллион входных токенов, $5 за миллион выходных.

| Шаг | Вход | Выход | Цена |
|---|---|---|---|
| Аналіз | ~1.5k | ~2k | $0.011 |
| План | ~3k | ~1.5k | $0.011 |
| Побудова | ~6k | ~6k | $0.036 |
| **Итого** | | | **≈ $0.06 за урок** |

Около 350 уроков на $20. На Opus 5 тот же урок стоил бы ~$0.30.

## Если качество не устроит

Поднимайте модель **на втором шаге**, а не на третьем. Третий выглядит дороже
всех по токенам, но задача там механическая. Решения принимает второй.

```bash
npm run make:blueprint -- 4297706 claude-sonnet-5
```

Первый аргумент — id вашего вебхука, второй — модель. Команда пересоберёт
blueprint целиком; если нужна другая модель только на одном шаге, поменяйте её
в готовом файле в поле `model` соответствующего модуля.

Меняйте по одному шагу и смотрите на результат — с тремя стадиями видно, какая
именно ошиблась. Это и есть главный плюс разбивки перед одним большим запросом.
