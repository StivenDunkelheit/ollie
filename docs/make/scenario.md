# Сценарий Make: генерация урока

Три вызова Claude Haiku 4.5 подряд, каждый решает одну задачу. Разбивка не
прихоть: Haiku дешёвая, но на одном запросе, где надо одновременно
проанализировать сорок задач, отобрать десять, выстроить их по сложности и
развернуть в полную схему урока — она сбоит. По шагам справляется.

```
Webhook  →  Webhook response 200  →  1. Аналіз  →  2. План  →  3. Побудова  →  Callback в Ollie
                                          └── Error handler → Callback зі status: failed
```

## Модуль 1 — Custom webhook

Уже создан: `My OLLIO DATA`. Его URL лежит в `GENERATION_WEBHOOK_URL`.

Чтобы Make узнал структуру входящих данных, при выключенном сценарии нажмите
**Redetermine data structure** и отправьте образец:

```bash
curl -X POST http://localhost:3000/api/dev/generation-sample
```

Что приходит — в [../generation-webhook.md](../generation-webhook.md).

## Модуль 2 — Webhook response

**Обязателен и ставится сразу вторым.** Без него Make держит HTTP-соединение до
конца сценария, а наше приложение ждёт ответа только 30 секунд и пометит урок
как неудавшийся, хотя генерация идёт.

| Поле | Значение |
|---|---|
| Status | `200` |
| Body | `{"accepted":true}` |

## Модуль 3 — Аналіз задач

**Anthropic Claude → Create a Message**

| Поле | Значение |
|---|---|
| Model | `claude-haiku-4-5` |
| Max tokens | `8000` |

`effort` и extended thinking у Haiku 4.5 не задавайте — она их не принимает.

**System prompt:**

```
Ти аналізуєш сирий список задач, який дав репетитор. Нічого не відбираєш і не будуєш — лише розбираєш.

Для КОЖНОЇ задачі з тексту визнач:
- n — порядковий номер у тексті
- text — умова дослівно, не змінюй жодного числа
- difficulty — складність від 1 (найлегша) до 5 (найважча), відносно рівня класу
- skill — коротка назва навички, яку задача перевіряє
- duplicate_of — номер задачі, дублікатом або дуже схожою на яку вона є, інакше null
- value — навчальна цінність: high, medium або low. Задача, що нічого не перевіряє або повторює вже наявну, має low
- answer — правильна відповідь, якщо вона є в тексті або однозначно обчислюється, інакше null

Заборонено: вигадувати задачі, змінювати умови, здогадуватися про відповідь без упевненості.

Оцінюй складність відносно одна одної, а не абсолютно: серед відібраних мають бути і найлегші, і найважчі.

Поверни ЛИШЕ JSON, без пояснень і без markdown:
{"tasks":[{"n":1,"text":"...","difficulty":1,"skill":"...","duplicate_of":null,"value":"high","answer":"..."}]}
```

**User message:**

```
Клас: {{1.input.grade}}
Тема: {{1.input.topic}}

Задачі:
{{1.input.source_text}}
```

## Модуль 4 — План уроку

**Anthropic Claude → Create a Message**, `claude-haiku-4-5`, max tokens `8000`.

Здесь решается всё: что взять, в каком порядке, каким интерактивом подать.
Правила тянутся прямо из вебхука, поэтому при их изменении в коде сценарий
править не нужно.

**System prompt:**

```
Ти складаєш план уроку з уже проаналізованих задач. Повних текстів завдань тут не пишеш — лише вирішуєш, що і в якому порядку буде.

ВІДБІР
{{join(1.rules.selection; newline)}}

СКЛАДНІСТЬ — НАЙВАЖЛИВІШЕ
{{join(1.rules.difficulty; newline)}}

РІЗНОМАНІТНІСТЬ
{{join(1.rules.variety; newline)}}

СТРУКТУРА
{{join(1.rules.structure; newline)}}

ТАЙМЕР
{{join(1.rules.timer; newline)}}

СЮЖЕТ І ОФОРМЛЕННЯ
{{join(1.rules.story; newline)}}

ЗАПАСНІ ЗАВДАННЯ
{{join(1.rules.spares; newline)}}

ДОСТУПНІ ІНТЕРАКТИВИ
{{join(map(1.reference.interactives; "description"); newline)}}

ДОСТУПНІ ТЕМИ ОФОРМЛЕННЯ
{{join(map(1.reference.themes; "slug"); ", ")}}

Перед відповіддю перевір себе:
1. difficulty у блоках task не спадає зліва направо.
2. Останнє завдання складніше за перше.
3. Два однакових інтерактиви не стоять підряд.
Якщо якась умова порушена — перебудуй план, а не виправдовуйся.

Поверни ЛИШЕ JSON, без пояснень і без markdown:
{"theme":"slug або none","story":{"character_name":"...","intro":"...","outro":"..."} або null,"blocks":[{"kind":"intro|story|task|reward|boss|final_quiz|stats|finish","task_n":номер або null,"interactive":"тип або null","difficulty":число або null,"timer_sec":число або null,"is_bonus":false,"note":"що має бути в блоці"}]}
```

**User message:**

```
Назва уроку: {{1.input.title}}
Клас: {{1.input.grade}}
Тема: {{1.input.topic}}
Оформлення: {{1.input.theme}}
Запасні завдання: {{1.input.generate_spares}}

Проаналізовані задачі:
{{3.content[].text}}
```

## Модуль 5 — Побудова уроку

**Anthropic Claude → Create a Message**, `claude-haiku-4-5`, max tokens `16000`.

Решений здесь не принимается — только разворачивание плана в полную схему.
Поэтому модель почти не думает и почти не ошибается.

**System prompt:**

```
Ти оформлюєш готовий план уроку у фінальний JSON за схемою.

Рішення вже ухвалені: набір задач, їх порядок, типи інтерактивів, difficulty, тема оформлення. Не змінюй нічого з цього. Твоя робота — розгорнути план у повні блоки.

Умови задач бери дослівно з аналізу. Правильні відповіді — звідти ж.

ВИМОГИ ДО ЗМІСТУ
{{join(1.rules.content; newline)}}

ТЕХНІЧНІ ВИМОГИ
- id короткі, латиницею, унікальні в межах усього уроку
- у fill_blank пропуски позначай у тексті як {{id}}; кожен має запис у blanks з усіма прийнятними варіантами відповіді, включно з різними формами запису числа
- у boss полe hp дорівнює кількості раундів
- у sort масив items подавай у перемішаному порядку, правильний — у correct_order
- кожне завдання kind=task обовʼязково має поле difficulty з плану

Поверни ЛИШЕ JSON за схемою, без пояснень і без markdown.

СХЕМА:
{{1.output_schema}}
```

**User message:**

```
ПЛАН УРОКУ:
{{4.content[].text}}

ПРОАНАЛІЗОВАНІ ЗАДАЧІ:
{{3.content[].text}}
```

## Модуль 6 — Віддати урок

**HTTP → Make a request**

| Поле | Значение |
|---|---|
| URL | `{{1.callback.url}}` |
| Method | `POST` |
| Body type | `Raw` |
| Content type | `JSON (application/json)` |

**Request content:**

```
{
  "lesson_id": "{{1.lesson_id}}",
  "token": "{{1.callback.token}}",
  "status": "ok",
  "lesson": {{5.content[].text}},
  "meta": {
    "model": "claude-haiku-4-5",
    "input_tokens": {{3.usage.input_tokens + 4.usage.input_tokens + 5.usage.input_tokens}},
    "output_tokens": {{3.usage.output_tokens + 4.usage.output_tokens + 5.usage.output_tokens}}
  }
}
```

`lesson` подставляется **без кавычек** — там уже готовый JSON от модели.
`lesson_id` и `token` в кавычках, это строки.

## Error handler

Правой кнопкой по модулю 5 → **Add error handler** → **Resume** → внутри
обработчика HTTP-модуль:

```
{
  "lesson_id": "{{1.lesson_id}}",
  "token": "{{1.callback.token}}",
  "status": "failed",
  "error": "{{5.error.message}}"
}
```

Без него сорвавшаяся генерация оставит урок в состоянии «генерується»
навсегда — викладач будет смотреть на крутящийся индикатор.

## Что делает наше приложение с результатом

Урок принимается только если проходит проверки:

| Проверка | Что отклоняется |
|---|---|
| Схема | лишние или отсутствующие поля, неверные типы |
| Ссылки | `correct_id` не из `options`, пропуск `{{id}}` без записи в `blanks`, `hp` ≠ числу раундов |
| Кривая сложности | задание легче предыдущего |
| Рост сложности | последнее задание не сложнее первого |

При отказе приходит `422` со списком причин в поле `issues` — он виден в
истории выполнения Make. По нему и правится промпт: не наугад, а по конкретной
претензии.

## Стоимость

Haiku 4.5 — $1 за миллион входных токенов, $5 за миллион выходных.

| Шаг | Вход | Выход | Цена |
|---|---|---|---|
| Аналіз | ~1.5k | ~2k | $0.011 |
| План | ~3k | ~1.5k | $0.011 |
| Побудова | ~6k | ~6k | $0.036 |
| **Итого** | | | **≈ $0.06 за урок** |

Около 350 уроков на $20. Для сравнения, тот же урок на Opus 5 обошёлся бы
примерно в $0.30.

## Если качество не устроит

Дешевле всего поднять только третий шаг — там больше всего выходных токенов,
но задача самая механическая, и рост качества там наименьший. Смысл имеет
поднимать **второй** шаг: именно он решает, какие задачи взять и как их
выстроить. Замените в модуле 4 модель на `claude-sonnet-5` — урок подорожает
центов на пять, а отбор станет заметно осмысленнее.

Меняйте по одному шагу и смотрите на результат: с тремя стадиями видно, какая
именно ошиблась, — это и есть главный плюс разбивки перед одним большим
запросом.

## Если приложение Anthropic в Make недоступно

Тогда HTTP-модуль на `https://api.anthropic.com/v1/messages` с заголовками
`x-api-key` и `anthropic-version: 2023-06-01`. Но учтите: в сыром JSON-теле
Make не экранирует подставляемые значения, а текст задач содержит переводы
строк и кавычки. Понадобится модуль **JSON → Create JSON** перед каждым
HTTP-вызовом: он собирает тело из полей и экранирует сам. Это плюс три модуля
к сценарию — поэтому приложение Anthropic предпочтительнее.
